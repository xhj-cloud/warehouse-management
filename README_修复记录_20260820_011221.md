## 修复的 5 个高危漏洞（H1–H5）

### H1 · 系统性存储型 XSS（前端零转义）
**问题**：所有表格用 `innerHTML` 直接拼接用户可控数据（商品名/客户名/文件名/AI 解析结果），且内联 `onclick="quickStockIn(id,'${p.name}')"` 里单引号可逃逸出属性/JS 字符串。Excel 导入一个名为 `<img onerror=...>` 的商品即可触发，任何用户打开对应页面即中招。

**怎么改**（`static/js/app.js`）：
1. 新增 `escapeHtml(v)` 工具函数（转义 `& < > " '` 五个字符），所有经 `innerHTML` 渲染的用户数据先转义。
2. 新增 `num(v)` 数字强转，内联 `onclick/onblur/onchange` 里的 `id`/`index` 一律 `num(...)` 处理为纯数字。
3. **内联处理器不再传递字符串参数**：`quickStockIn/quickStockOut/deleteProduct/showBatchDetail/editInventory` 的签名都改为只收数字 id，名称从内存缓存（`currentProducts`/`currentInventory`）按 id 找回，从根上杜绝属性逃逸。
4. 覆盖约 15 处渲染函数：商品、库存、交易、上传记录、分类、供应商、客户、出库单明细、进货批次弹窗、审计日志、AI 智能导入/AI 分析页/入库识别结果、仪表盘卡片等。

### H2 · AI 分析页未转义
**问题**：聊天页有 `renderChatReply` 转义，但 `/api/ai/analyze` 的 `runAIAnalysis` 里 `container.innerHTML = \`${result.data}\`` 漏了——AI 回显被污染的商品名即可注入 HTML（存储型 XSS 的又一入口）。

**怎么改**：`runAIAnalysis` 复用 `renderChatReply`（先整体转义再渲染），错误信息也走 `escapeHtml`。

### H3 · "设为绝对值"并发竞态（读-改-写非原子）
**问题**：上轮把 `stock_in/out` 改成了原子增减，但"设置为目标值"仍是 `SELECT quantity → 算 delta → 增减` 三步。并发两个"设为50"（当前100）会各自算 delta=-50 连减两次 → 库存变 0 而非 50。

**怎么改**（`app.py`）：在三处读旧值处加 `FOR UPDATE` 行锁：
1. `_apply_inventory_change`（库存/商品 PUT"设为绝对值"）
2. `_do_ai_set_quantity`（AI 库存调整）
3. Excel 全量覆盖模式导入的 `old_inv` 查询

`FOR UPDATE` 在事务内锁住目标行，后到的并发请求阻塞到前一个提交，读到的必然是最新值，彻底消除丢失更新。（`created_at`/流水不受影响，均在同一事务内。）

### H4 · 全 API 无认证（debug=True 已保留）
**问题**：约 30 个 API 无任何鉴权且绑定 `0.0.0.0`，内网任何机器的 `curl` 都能直接改库存/删商品/拉全部数据；`record_id`/DB 密码默认值可预测。

**怎么改**：
- `config.py`：新增 `AUTH_USER` / `AUTH_PASSWORD` / `AUTH_DISABLED`（从环境变量读取）。
- `app.py`：`before_request` 钩子对 `/api/*` 与 `/uploads/*` 强制 HTTP Basic Auth，用 `hmac.compare_digest` 常量时间比较；未认证返回 401 + `WWW-Authenticate`（浏览器自动弹登录框）；失败时带 `WWW-Authenticate: Basic` 头。页面与静态资源不拦截。
- 环境变量未配置 `AUTH_PASSWORD` 时认证禁用并打印警告（仅限本地联调）。
- **部署配置**：systemd 服务已注入 `AUTH_USER=admin`、`AUTH_PASSWORD`（随机强密码，见附录）。

### H5 · 手工出库单无事务（半截出库）
**问题**：前端逐项调 `stock-out`，第 2 项失败时第 1 项已扣减且提示"出库成功"，无法回滚；对比 AI `create_order` 有预检+单事务，手工路径漏网。

**怎么改**：
- `app.py`：新增 `POST /api/order/submit`——**先预检**所有商品（存在性 + `SELECT ... FOR UPDATE` 库存充足），任一不满足返回 400 且**整体不执行**；全部通过后在**单事务**内逐项原子扣减，任一失败整体回滚；每单生成独立批次号 `出库单-YYYYMMDDHHMMSS-随机`，写操作流水与审计日志同事务。
- `app.js`：`submitAndDownload` 改为一次调用 `/api/order/submit`，成功后 UI 提示"出库成功"并发起 Excel 下载，失败提示"未扣减库存"。

## 🔐 账户管理功能（本次新增）

在「高危漏洞修复」基础之上，把原来单用户（系统变量）认证升级为**多账户数据库用户管理体系**。

### 改了什么
1. **`users` 表**（`init_db.sql`）：`id, username(UNIQUE), password_hash, role('admin'/'user'), created_at/updated_at`。密码用 werkzeug `scrypt` 加盐哈希存储，**绝不明文落库**。
2. **`models.py`** 新增 `UserModel`：`create / get_by_username / get_all / authenticate / update_password / delete / count_admins`，另有 `seed_admin_if_empty()`——users 表为空时自动引导 `admin/admin123` 管理员账户（幂等，不会覆盖已有账户）。
3. **`app.py` 认证改造**：`before_request` 认证改为**优先查 users 表**（`UserModel.authenticate`），保留 systemd 的 `AUTH_USER/AUTH_PASSWORD` 作为超级管理员兜底；新增 `_is_admin()` 角色判断与 `_current_username()`（用于审计日志的 operator 归属）。
4. **账户 API**（仅管理员可调用）：
   - `GET /api/auth/me` —— 返回当前用户与是否管理员（供前端显示"账户管理"入口）
   - `GET /api/users` —— 账户列表（**不下发密码哈希**）
   - `POST /api/users` —— 创建账户（用户名空/重复、密码<6位 均拒绝）
   - `DELETE /api/users/<id>` —— 删除账户（**不能删自己、不能删最后一个管理员**）
5. **前端**：侧边栏新增「账户管理」入口（仅管理员显示）；页面含创建表单（用户名/密码/角色）+ 用户列表；新增 `loadAuthInfo / loadAccounts / createUser / deleteUser`。

### 逻辑要点（怎么改的）
- **密码安全**：`generate_password_hash()` 生成 scrypt 哈希，登录用 `check_password_hash()` 校验——即使数据库泄露，也无法反推出明文密码。
- **审计**：创建/删除账户都写入 `audit_log`，operator 记录操作者。
- **防误删**：保护两个"不能"——不能删除自己、不能删除最后一个管理员，避免把系统锁死。
- **前端权限**：只有 `is_admin` 为真时才显示「账户管理」导航（后端仍强制校验，防绕过）。

## 🔄 登录方式升级：Basic Auth → Session 登录（修复"每次刷新都要重新登录"）

### 问题
原认证用 **HTTP Basic Auth**（浏览器弹窗登录框），凭据只在浏览器会话内缓存，
刷新页面/重开浏览器就要求重新输入用户名密码，体验差。

### 改了什么（怎么改的）
1. **新增登录页** `templates/login.html`：用户名 + 密码表单，独立样式，POST 到 `/api/login`。
2. **新增接口**：
   - `POST /api/login` —— 校验用户名密码（users 表优先、环境变量兜底），校验通过后写入
     **Flask session** 并标记 `permanent=True` → 签发 **7 天持久 cookie**
     （`PERMANENT_SESSION_LIFETIME=7天`，`HttpOnly` + `SameSite=Lax`）。
   - `POST /api/logout` —— 清空 session，浏览器收到 `Set-Cookie: session=; Max-Age=0` 立即删除。
   - `GET /api/auth/me` —— 从 session 读当前用户与角色。
3. **`before_request` 改造**：未登录访问 `/` 与页面 → **302 重定向到 `/login`**；
   访问 `/api/*`、`/uploads/*` → **401 JSON（code=AUTH_REQUIRED）**；
   `/login`、`/api/login`、`/static/*` 公开。
4. **前端**：
   - `fetchAPI` 收到 401 + `AUTH_REQUIRED` 时自动跳转 `/login`（登录接口本身除外，防死循环）。
   - 顶部栏新增「退出登录」按钮 + 当前用户名显示；侧边栏账户管理入口仍按角色显隐。
5. **逻辑要点**：登录态存于 **服务端签名 cookie**（客户端不可伪造篡改），
   刷新页面/重开浏览器都保持登录，直到 **7 天过期或主动退出**。

### 服务器验证（全部通过）
| 场景 | 结果 |
|------|------|
| 未登录访问 `/` | 302 → `/login` |
| 未登录访问 `/api/dashboard` | 401 `AUTH_REQUIRED` |
| `POST /api/login` admin/admin123 | 成功，签发 7 天 HttpOnly cookie |
| 携带 cookie 访问 `/`、`/api/dashboard`、`/api/auth/me` | 全部 200 |
| `POST /api/logout` | 返回 `Set-Cookie: session=; Max-Age=0`（浏览器立即清除）|
| 普通用户 bob 访问 `/api/users` | 403（仅管理员）|

### 覆盖文件
- `app.py`（session 认证 + login/logout 接口 + before_request 重定向）
- `templates/login.html`（新增登录页）
- `templates/index.html`（退出登录按钮 + 当前用户显示）
- `static/js/app.js`（401 跳转登录页 + logoutUser）
- `tests/test_api.py`（新增 4 个登录验证用例）
