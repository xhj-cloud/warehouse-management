## 修复的 5 个高危漏洞（H1–H5）

### H1 · 系统性存储型 XSS（前端零转义）
**问题**：所有表格用 `innerHTML` 直接拼接用户可控数据（商品名/客户名/文件名/AI 解析结果），且内联 `onclick="quickStockIn(id,'${p.name}')"` 里单引号可逃逸出属性/JS 字符串。Excel 导入一个名为 `<img onerror=...>` 的商品即可触发，任何用户打开对应页面即中招。

**怎么改**（`static/js/app.js`）：
1. 新增 `escapeHtml(v)` 工具函数（转义 `& < > " '` 五个字符），所有经 `innerHTML` 渲染的用户数据先转义。
2. 新增 `num(v)` 数字强转，内联 `onclick/onblur/onchange` 里的 `id`/`index` 一律 `num(...)` 处理为纯数字。
3. **内联处理器不再传递字符串参数**：`quickStockIn/quickStockOut/deleteProduct/showBatchDetail/editInventory` 的签名都改为只收数字 id，名称从内存缓存（`currentProducts`/`currentInventory`）按 id 找回，从根上杜绝属性逃逸。
4. 覆盖约 15 处渲染函数：商品、库存、交易、上传记录、分类、供应商、客户、出库单明细、进货批次弹窗、审计日志、AI 智能导入/AI 分析页/入库识别结果、仪表盘卡片等。

### H2 · AI 分析页未转义
**问题**：聊天页有 `renderChatReply` 转义，但 `/api/ai/analyze` 的 `runAIAnalysis` 里 `container.innerHTML = \`${result.data}\`` 漏了——AI 回显被污染的商品名即可注入 HTML（存储型 XSS 的又一入口）。

**怎么改**：`runAIAnalysis` 复用 `renderChatReply`（先整体转义再渲染），错误信息也走 `escapeHtml`。

### H3 · "设为绝对值"并发竞态（读-改-写非原子）
**问题**：上轮把 `stock_in/out` 改成了原子增减，但"设置为目标值"仍是 `SELECT quantity → 算 delta → 增减` 三步。并发两个"设为50"（当前100）会各自算 delta=-50 连减两次 → 库存变 0 而非 50。

**怎么改**（`app.py`）：在三处读旧值处加 `FOR UPDATE` 行锁：
1. `_apply_inventory_change`（库存/商品 PUT"设为绝对值"）
2. `_do_ai_set_quantity`（AI 库存调整）
3. Excel 全量覆盖模式导入的 `old_inv` 查询

`FOR UPDATE` 在事务内锁住目标行，后到的并发请求阻塞到前一个提交，读到的必然是最新值，彻底消除丢失更新。（`created_at`/流水不受影响，均在同一事务内。）

### H4 · 全 API 无认证（debug=True 已保留）
**问题**：约 30 个 API 无任何鉴权且绑定 `0.0.0.0`，内网任何机器的 `curl` 都能直接改库存/删商品/拉全部数据；`record_id`/DB 密码默认值可预测。

**怎么改**：
- `config.py`：新增 `AUTH_USER` / `AUTH_PASSWORD` / `AUTH_DISABLED`（从环境变量读取）。
- `app.py`：`before_request` 钩子对 `/api/*` 与 `/uploads/*` 强制 HTTP Basic Auth，用 `hmac.compare_digest` 常量时间比较；未认证返回 401 + `WWW-Authenticate`（浏览器自动弹登录框）；失败时带 `WWW-Authenticate: Basic` 头。页面与静态资源不拦截。
- 环境变量未配置 `AUTH_PASSWORD` 时认证禁用并打印警告（仅限本地联调）。
- **部署配置**：systemd 服务已注入 `AUTH_USER=admin`、`AUTH_PASSWORD`（随机强密码，见附录）。

### H5 · 手工出库单无事务（半截出库）
**问题**：前端逐项调 `stock-out`，第 2 项失败时第 1 项已扣减且提示"出库成功"，无法回滚；对比 AI `create_order` 有预检+单事务，手工路径漏网。

**怎么改**：
- `app.py`：新增 `POST /api/order/submit`——**先预检**所有商品（存在性 + `SELECT ... FOR UPDATE` 库存充足），任一不满足返回 400 且**整体不执行**；全部通过后在**单事务**内逐项原子扣减，任一失败整体回滚；每单生成独立批次号 `出库单-YYYYMMDDHHMMSS-随机`，写操作流水与审计日志同事务。
- `app.js`：`submitAndDownload` 改为一次调用 `/api/order/submit`，成功后 UI 提示"出库成功"并发起 Excel 下载，失败提示"未扣减库存"。
